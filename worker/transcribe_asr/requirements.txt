# Qwen3-ASR's torch pin — a **record of a resolved conflict, not an install.**
#
# **Nothing installs this file.** Qwen3-ASR has no environment of its own: it runs
# in the main one, on `torch==2.10.0+cu128` from `worker/requirements.txt` (and
# `qwen-asr==0.0.6` itself installed there with `--no-deps`, so its own
# `accelerate`/torch declarations never enter the resolution).
#
# It is kept because it records *why* an environment was needed at all — the
# problem this file solved is the problem `--no-deps` now solves, and a reader who
# finds only the `--no-deps` line cannot tell whether it was a shortcut or a fix.
#
# The conflict it pinned around:
#
#   `qwen-asr==0.0.6` pins `transformers==4.57.6` exactly, but declares torch only
#   through `accelerate==1.12.0`, which asks for `torch>=2.0.0` — no upper bound.
#   pip therefore took whatever was newest at build time. One build resolved
#   **torch 2.14.0**, pulled its CUDA 13.0 stack, and that environment then did
#   real work: a 197 s cover transcribed lyrics in 78.37 s and the job completed.
#
#   2.14.0 was therefore proven — and still not reproducible, because an image
#   whose contents depend on the day it was built reports nothing when that
#   changes. This pin froze what had been demonstrated.
#
# The resolution order mattered at the time: this file was applied **before**
# `qwen-asr`, so pip found torch already satisfied and skipped re-picking it.
#
# Two facts from this episode are still load-bearing elsewhere:
#
#   * **`torch 2.14.0` from plain PyPI is a CUDA build.** Unlike 2.10.0, whose
#     PyPI wheel is CPU-only, 2.14.0 ships the CUDA build (554 MB) and brings
#     `nvidia-*` cu13 packages as ordinary dependencies. It carries no `+cuXXX`
#     local version identifier, which is why `check_env.verify_cuda_build` reads
#     `torch.version.cuda` rather than pattern-matching the version string — a
#     check that looked for the identifier rejected this working build.
#   * **A transcription that is subtly wrong because of a torch gap still returns
#     200.** That is why both transcription children report their own `environment`
#     (interpreter, python, torch, cuda) in `result.json`, and why the parent
#     passes it through into the job response. It is how the unification
#     experiment was answered from its own output.

torch==2.14.0
