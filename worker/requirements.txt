# Runtime dependencies — YuE2 RunPod Serverless worker.
#
# Every pin here is exact. `_config/conventions.md` forbids loose ranges on
# purpose: these wheels are known to conflict across model families, and a
# resolver left to its own judgement will happily pick a combination that
# imports and then fails mid-generation.
#
# The authoritative source for the first eight pins is the `yue2_infer-0.1.5`
# wheel's own METADATA (`Requires-Dist`), read directly from the HF repo — not
# the model card, not shared/dependency-pins.md, both of which omit safetensors,
# tiktoken and soundfile. See output/create-mode-worker.md for that correction.
#
# PyTorch is served from the CUDA 12.8 index; `torch==2.10.0` on plain PyPI is a
# CPU-only build and would install cleanly and then fail on `device="cuda"`.
--extra-index-url https://download.pytorch.org/whl/cu128

torch==2.10.0
# torchaudio must version-match torch. It is here because SheetSage2's code —
# which the unification probe imports into this environment — uses
# `torchaudio.load`, `.info` and `.functional.resample`. Those are stable APIs
# and torchaudio 2.10.0 ships for cu128/cp311, so this is a missing package
# rather than a version conflict. It is also what a unified environment would
# need regardless.
torchaudio==2.10.0

huggingface-hub==0.36.2
safetensors==0.7.0
tiktoken==0.12.0

# --- SheetSage2's non-torch requirements, for the unification probe ---------
#
# Derived from SheetSage2's own `requirements.txt` and `requirements-render.txt`
# (read from m-a-p/SheetSage2, not guessed), minus what is already pinned above
# and minus what the probe does not need.
#
# `mir_eval` and `pretty_midi` are **module-scope** imports in
# `midi_sheetsage2.py`:
#
#     import mir_eval.chord
#     import numpy as np
#     import pretty_midi
#
# so they are required to import the model at all, not merely to render.
#
# `playwright` (from requirements-render.txt) is deliberately absent. It is a
# browser automation library needing a Chromium download, and
# `rendering_sheetsage2.py` imports it *inside* a function, not at module scope.
# The authors made rendering optional on purpose and the image stays that way.
mir_eval==0.8.2
# `pretty_midi` declares no dependencies at all — no numpy, no mido — even though
# it uses both. That is why `mido` is pinned explicitly rather than left to the
# resolver to notice.
pretty_midi==0.2.10
mido==1.3.3

# --- Qwen3-ASR's runtime dependencies -----------------------------------------
#
# `cover`'s lyric transcription runs here, in this environment, alongside YuE2 and
# SheetSage2. It was originally given its own venv (`/opt/venvs/qwen3-asr`) on the
# assumption its pins could not coexist with these; the unification experiment
# tested that assumption, it was wrong, and the venv was deleted. The pins below
# are what the ASR family actually needs on this stack.
#
# **`qwen-asr` itself is deliberately NOT in this file.** This file is installed
# with full dependency resolution, and `qwen-asr==0.0.6` pins
# `accelerate==1.12.0` while the YuE2 wheel pins `accelerate==1.13.0` — two exact
# pins that cannot both hold, so pip aborts with `ResolutionImpossible`. Listing
# it here failed a build exactly that way. It is installed with `--no-deps` in
# the Dockerfile instead, after this file, which sidesteps a conflict between two
# pins that neither package actually uses.
#
# The pins below are what `qwen_asr` really imports, read from its wheel with
# `ast` rather than from its declared list. Its declared `gradio`, `flask` and
# `vllm` are the CLI and the optional vllm backend (the one inference-path
# `vllm` import sits inside a `try/except`), and `pytz`, `sox`, `qwen_omni_utils`
# and `accelerate` are declared and never imported — which is why none of them
# are here. `numpy`, `scipy` and `torch` it also imports are already pinned above.
nagisa==0.2.11
soynlp==0.0.493
librosa==0.11.0

# Worker transport and egress. Not pinned by the model wheel — these are ours.
runpod==1.12.0
boto3==1.43.97
